# Native adhan scheduling
Local Android Flutter plugin participates in generated plugin registration for the UI and headless WorkManager engines. Exact-mode adhan requests with an available recording arm the native alarm; the existing plugin schedules a silent companion notification. Nonaccepted native requests, early reminders and unsupported platforms use system sound. An empty native replacement cancels stale alarms. Existing ReminderLock serializes updates. Boot/update restores future persisted records. Migration cancels old audible notifications before scheduling native playback. No atomic transaction across Android AlarmManager and notification plugin; interruption can require a subsequent refresh. Validate headless registration, revocation, duplicate suppression, reboot and physical-device playback before production use.
