# Android background reminders (experimental)
WorkManager registers a unique 12-hour periodic task; actual timing depends on Android. It needs no network. The headless callback reloads preferences and timezone data, calculates a six-day plan using the existing repository, and never prompts for permissions. SQLite exclusive transactions serialize scheduler calls from the foreground and background engines. This is not an atomic transaction spanning AlarmManager and preferences; plugin receivers and OS events are outside the lock. A failed task returns false for retry. Last successful background execution is saved in reminder_last_background_success.
Test on Android 12–16: launch, background refresh, concurrent manual apply, change city, revoke exact-alarm permission, reboot, process death and force stop. Force stop and OEM restrictions may prevent execution until the app is reopened. Verify plugin cache coherence and database lock behavior across Flutter engines before production release. No iOS background task is registered. Build and runtime validation pending.
