# MIHRAB Web Push — backend foundation

Worker module entry: src/index.mjs. Bind D1 as DB and apply migrations/0001_initial.sql. Use the Cloudflare cf CLI or dashboard to provision; no account-specific resources are assumed. Configure an explicit ALLOWED_ORIGINS list (exact HTTPS origins), VAPID_PUBLIC_KEY, and leave ENABLE_REGISTRATION unset until consent and abuse controls are verified. CORS alone is not abuse prevention; configure edge rate limiting and verify subscription ownership before public launch. Never log request bodies, endpoints, keys or tokens. No private keys belong in Git.

API: GET /health; GET /v1/vapid-public-key; POST /v1/subscriptions with {subscription,locale,consent:true}; PUT /v1/subscriptions/:id/schedule with Bearer token and {reminders:[{id,kind,dueAt,lead}]}; DELETE /v1/subscriptions/:id with Bearer token. Times are UTC epoch milliseconds, future only, six-day window. Client must renew before the window expires; no guarantee of continuous reminders while closed beyond six days. Token is returned once; secure client storage and lost-token recovery are outstanding. Endpoint allowlist is deliberately limited and needs real-device validation. Schedule API response accepted counts input rows, not actual new inserts.

Run node --test and node --check src/index.mjs. Scheduled handler currently purges expired subscriptions and old rows only. No Web Push payload encryption, dispatch, delivery retry, client subscription UI or consent flow yet. Do not enable registration publicly until implemented and reviewed. No deployment or end-to-end test has occurred.
